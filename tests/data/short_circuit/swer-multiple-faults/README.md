# Validation case: simultaneous short circuits in a SWER chain

IEC 60909 short circuits (maximum voltage scaling) with several simultaneous faults in the `swer-chain` network of `power_flow/single-phase-transformer`, without loads: a 22 kV three-phase feeder (nodes 1 and 2), a SWER isolating transformer (`ab` → `a`, 22 kV / 12.7 kV, earth electrode of 5 + j0.1 Ω), a 20 km SWER line (nodes 3 and 4) and two SWER distribution transformers (`a` → `a`, 12.7 kV / 240 V) to the 240 V nodes 5 (behind the transformer with a from-side tap at +2.5 %) and 6. All faults are single-phase to ground on phase a, since all faults of one calculation must have the same type and phase. The input holds the faults 601, 602 and 603; each scenario switches its faults on (status 1) and the others off. It is a batch of two scenarios:

- fault 601 at the end of the SWER line (node 4) with `r_f` = 10 Ω and fault 602 at the 240 V node 6 with `r_f` = 0.05 Ω: 168.046 A and 583.723 A; fault 603 is off (`i_f` = 0);
- fault 601 at the 22 kV three-phase node 2 with `r_f` = 5 Ω, fault 602 at the 240 V node 5 (bolted) and fault 603 at the start of the SWER line (node 3) with `z_f` = 20 + j10 Ω (an OpenDSS `Reactor`, as in `swer-fault-impedance`): 1594.40 A, 525.268 A and 129.423 A. This combines a three-phase node with SWER and 240 V nodes in one calculation.

Each fault upstream of another one has an impedance. A bolted fault at the start of the SWER line would leave the SWER and 240 V nodes behind it without voltage, so the faults there would get no current and test nothing; a bolted fault at node 2 would strongly lower the voltage of the isolating transformer. With these impedances every fault current is far from zero. PGM and OpenDSS agree to about 3.7e-10 relative, so the case passes with rtol 1e-8 and atol 1e-8 with a margin of more than 10x.

## Generation

The input (`input.json`), the OpenDSS model (`test.dss`) and the expected output are generated by `tests/data/generators/reduced_phase_opendss_cases.py`, with OpenDSS (via `opendssdirect.py`) as the reference solver. Do not edit the files by hand; change the case definition in the script and regenerate. The modelling choices and the command to run are described at the top of the script.
